# Janus 客户端 SDK 业务对接指南

本文档面向**业务单体**（需要接入 Janus 统一认证中心的应用）的开发者，介绍如何使用
`janus-client-spring-boot-starter` 完成对接。**只需配置 `janus.client.*` 几项，即可获得单点登录、用户上下文注入、用户/机构/角色查询、权限门禁能力，业务代码零侵入。**

> 接入原理与源码结构见《模块解读》；本文档只讲"怎么用"。

---

## 一、前置条件

- 业务系统为 **Spring Boot 3 + Servlet** 应用（starter 依赖 `spring-boot-starter-web`）。
- 认证中心（Janus）已部署，且已在中心为你的应用分配：`client`（应用标识）、`secret-key`（签名密钥）、回调地址 `clientUrl`。
- JDK 17。

---

## 二、引入依赖

在业务系统的 `pom.xml` 中引入 starter：

```xml
<dependency>
    <groupId>com.janus</groupId>
    <artifactId>janus-client-spring-boot-starter</artifactId>
    <version>1.1.0</version>
</dependency>
```

无需再引入 Sa-Token、Caffeine 等，starter 已传递依赖。

### 2.1 获取构件

starter 已发布到 **Maven Central**（groupId `com.janus`），业务系统无需配置额外仓库，直接依赖即可。

如果暂时无法访问 Central（如内网环境），有两种替代方式：

- **本地安装**：克隆 Janus 源码，执行 `mvn install -pl janus-client-spring-boot-starter -am`，业务系统即可从本地仓库解析；
- **自建私服**：将 starter 构件 deploy 到团队私服，业务方 `settings.xml` 中加入该仓库地址，并把现有镜像的 `mirrorOf` 排除对应仓库 id（如 `*,!your-repo-id`），防止 `com.janus` 请求被公共镜像劫持。

## 三、基础配置

在 `application.yml`（或 `bootstrap.yml`）中配置：

```yaml
janus:
  client:
    # 认证中心地址
    server-url: http://localhost:8080
    # 应用标识
    client: order-service
    # 接口签名密钥
    secret-key: your-secret-key
    # 本系统外网/可访问地址，用于单点登出(SLO)回调：center → clientUrl + /sso/logoutCall
    client-url: http://localhost:8081
    # 可选：应用显示名，注册时上报中心，默认取 client
    app-name: 订单服务
```

### 配置项全表

> 全量配置模板已随 jar 发布：`classpath:application-janus-client.yml`（源码见 [src/main/resources/application-janus-client.yml](file:///data/work/Ideaworkspace/oauth/janus-client-spring-boot-starter/src/main/resources/application-janus-client.yml)）。
> 业务 `application.yml` 中 `spring.config.import: classpath:application-janus-client.yml` 即可引入查看；
> 正式接入请拷贝必配 4 项到业务 yml 并替换真实值（业务 application.yml 优先级更高）。
> 业务工程内输入 `janus.client` 也有 IDE 自动补全（starter 内置 configuration-processor）。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `janus.client.server-url` | 无 | 认证中心地址 |
| `janus.client.client` | 无 | 应用标识（= 中心注册名），必填 |
| `janus.client.secret-key` | 无 | 签名密钥，必填 |
| `janus.client.client-url` | 无 | 本系统访问地址，SLO 回调用，必填 |
| `janus.client.app-name` | 取 `client` | 注册上报的显示名 |
| `janus.client.monitor-enabled` | `true` | 是否开启监控端点 `/sso/janus/monitor` 与页面 |
| `janus.client.exclude-paths` | 见下 | 拦截器放行路径（`include-paths` 为空时生效） |
| `janus.client.include-paths` | 空 | 白名单拦截模式：配置后**只拦这些路径**，其余一律放行 |
| `janus.client.cache.max-size` | `50000` | Caffeine 最大缓存条数 |
| `janus.client.cache.expire-hours` | `12` | 写入后过期小时数（EMPTY 哨兵同 TTL） |

`exclude-paths` 默认已包含：`/sso/**`、`/`、`/index.html`、`/favicon.ico`、`/error`，并会自动追加
`/sso/janus/openApi/notify` 与监控端点。业务只需把**自己的静态页/公开接口**追加进去即可。

> **⚠ properties 文件中文乱码提醒**：Java `.properties` 规范按 ISO-8859-1 解码（yml 才是 UTF-8）。
> 若 `janus.client.*` 配置写在 `.properties` 中，`app-name` 等中文值必须用 Unicode 转义
> （如 `janus.client.app-name=AI\u7f51\u5173` 表示"AI网关"），否则注册到认证中心的显示名会是乱码；
> 或直接改用 `application.yml` 配置中文。

### 两种拦截模式

**默认：排除法（全拦 − 排除）**。拦截器挂 `/**`，适合"大多数请求都需要登录"的常规业务系统：

```
拦截 = 全部请求(/**) − exclude-paths
```

**可选：白名单法（include-paths）**。配置后拦截器**只挂声明的路径**，其余一律放行，适合
"少数路径才需要登录"的场景（如网关项目只有 `/admin/**` 需要登录，而代理路径前缀动态多变，
无法用排除法枚举）：

```yaml
janus:
  client:
    include-paths:
      - /admin/**     # 只有管理后台需要 SSO 登录
```

```
拦截 = 仅 include-paths（其余一律放行）
```

两种模式下 `exclude-paths`（含 starter 端点自动放行）均始终生效——即使白名单与内置端点
重叠（如写了 `/**`），`/sso/**`、通知、监控端点也不会被误拦。不配置 `include-paths` 则
行为与旧版本完全一致，向后兼容。

## 四、登录与登出

### 发起登录
浏览器/前端导航到本系统的 SSO 登录入口：

```
GET /sso/login?back=<登录成功后的回跳地址>
```

starter 会自动跳转认证中心，用户完成认证后，中心带着 `ticket` 跳回本系统的 `/sso/login?ticket=…&back=…`，
由 Sa-Token 客户端处理器验票、建立**本地会话**，再 302 回 `back`。

> 受保护 API（被拦截器命中）若未登录，直接返回 `401 JSON`，由前端自行引导跳 `/sso/login?back=当前页`。

### 登出
- **单点登出（默认）**：`/sso/logout` 会注销本应用本地会话，并通知认证中心注销中央会话，
  中心再向所有已注册客户端的 `clientUrl/sso/logoutCall` 推送全端注销。
- **仅退本应用**（保留其他系统登录）：`/sso/logoutByAlone`。

### 认证生命周期钩子（登录成功 / 退出）

由于 SSO 验票、会话建立与注销全部在 starter 内部托管完成，业务无需编写登录/注销 Controller。若业务系统需要在**登录成功**或**退出登录**时执行自定义逻辑（如同步业务用户档案、记录登录/登出审计日志、初始化租户配置、清理本地连接/缓存资源等），starter 提供了开箱即用的钩子机制，支持两种感知方式：

#### 方式一：实现 `JanusAuthHook` 接口（推荐）

只需声明一个 Spring Bean 实现 `JanusAuthHook`（方法均有默认空实现，可按需覆写）：

```java
package com.example.hook;

import com.janus.client.hook.JanusAuthHook;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

@Slf4j
@Component
public class MyAuthHook implements JanusAuthHook {

    /**
     * SSO 验票成功且本地会话建立后触发
     *
     * @param loginId    用户唯一标识（与 UserContext.getUid() 一致）
     * @param tokenValue 本次生效的会话 Token
     */
    @Override
    public void onLoginSuccess(String loginId, String tokenValue) {
        log.info("用户登录成功: uid={}, token={}", loginId, tokenValue);
        // 执行业务逻辑：如初始化本地用户、写入登录流水、统计在线等
    }

    /**
     * 本地会话注销、认证中心 SLO 回调推送或被踢下线时触发
     *
     * @param loginId    用户唯一标识（可能为 null）
     * @param tokenValue 本次注销的 Token（可能为 null）
     * @param logoutType 登出类型："logout"（主动登出）、"slo"（认证中心 SLO 全端注销推送）、"kickout"（被踢下线）
     */
    @Override
    public void onLogout(String loginId, String tokenValue, String logoutType) {
        log.info("用户退出: uid={}, token={}, type={}", loginId, tokenValue, logoutType);
        // 执行业务清理：如清除临时资源、断开 WebSocket、记录登出审计日志等
    }
}
```

> **高可用保护与多 Hook 支持**：
> - 支持声明多个 Hook Bean，支持通过 `@Order(n)` 指定执行先后顺序；
> - 单个 Hook 抛出异常会被 starter 捕获并记录 ERROR 日志，**绝对不会阻断** SSO 登录回跳、SLO 响应或影响其他 Hook 的执行。

#### 方式二：使用 Spring `@EventListener` 事件机制

如果不希望实现特定接口，也可直接监听 starter 发布的 Spring ApplicationEvent：

```java
import com.janus.client.event.JanusLoginSuccessEvent;
import com.janus.client.event.JanusLogoutEvent;
import org.springframework.context.event.EventListener;
import org.springframework.stereotype.Component;

@Component
public class MyAuthEventListener {

    @EventListener
    public void onLogin(JanusLoginSuccessEvent event) {
        // event.getLoginId(), event.getTokenValue()
    }

    @EventListener
    public void onLogout(JanusLogoutEvent event) {
        // event.getLoginId(), event.getTokenValue(), event.getLogoutType()
    }
}
```

## 五、获取当前登录用户

拦截器在每个受保护请求进入时，从本地会话取出 uid，回源拿到用户简要信息，注入 `UserContext`。
业务在 Controller/Service 中随时读取：

```java
import context.com.janus.client.UserContextHolder;

UserContext ctx = UserContextHolder.require();   // 未注入会抛 IllegalStateException
Long uid = ctx.getUid();
String username = ctx.getUsername();
String realName = ctx.getRealName();
Long deptId = ctx.getDeptId();
String deptName = ctx.getDeptName();
List<String> roles = ctx.getRoles();
List<String> authCodes = ctx.getAuthCodes();
```

`UserContext` 还提供门禁方法：

```java
if (ctx.hasRole("admin"))  { /* 管理员 */ }
if (ctx.hasAuth("order:export")) { /* 有权导出 */ }
```

> **注意**：`UserContextHolder.get()` 在放行路径、异步线程中可能返回 `null`；需保证身份语义处请用 `require()`。
> 已登录但用户在中心被删除/停用，拦截器仍返回 `401`，不会以空身份放行。

## 六、查询用户 / 机构 / 角色数据

注入统一门面 `JanusClient`，所有数据来自**本地缓存**（未命中自动签名回源中心），业务无需关心缓存与失效：

```java
import api.com.janus.client.JanusClient;

@Autowired
private JanusClient janusClient;

// 用户
UserInfoVO u = janusClient.getUserById("123");          // 永不返回 null；查无此人 exists=false
Map<String, UserInfoVO> map = janusClient.getUsersByIds(List.of("1", "2", "3")); // 单次上限 500 自动分片
List<UserInfoVO> list = janusClient.searchUsers("张");  // 登录名/姓名模糊（服务端分页搜索）

// 机构（部门）
DeptInfoVO org = janusClient.getOrgById("10");          // 按需回源，LRU 缓存
List<DeptInfoVO> children = janusClient.getOrgChildren("10"); // 层级查询
List<DeptInfoVO> orgHits = janusClient.searchOrgs("研发");     // 服务端分页搜索

// 角色
List<RoleInfoVO> roles = janusClient.listRoles();
RoleInfoVO r1 = janusClient.getRoleById("5");
RoleInfoVO r2 = janusClient.getRoleByKey("admin");
List<RoleInfoVO> roleHits = janusClient.searchRoles("admin");

// 职务与组织关系
PositionInfoVO pos = janusClient.getPositionById("p001");     // 单个职务详情（本地二级缓存）
List<PositionInfoVO> allPos = janusClient.listPositions();    // 职务列表（按职级权重降序）
UserInfoVO leader = janusClient.getOrgLeader("d001");         // 部门负责人（老大）
List<UserDeptPositionVO> members = janusClient.listOrgMembersWithPositions("d001"); // 部门全体成员及职务
```

> 推荐面向接口 `JanusClient` 注入，便于单测时用 mock 替换实现。

## 七、本地缓存与失效通知机制（了解即可）

| 维度 | 策略 |
|---|---|
| 用户缓存 | Caffeine LRU（默认 5w 条 / 12h）；未命中按 uid **批量回源**（500 分片）；查无此人写 **EMPTY 哨兵**防穿透；回源失败抛异常 |
| 机构缓存 | Caffeine LRU 按需缓存；未命中批量回源（500 分片），组织树按层级按需拉取（`orgs-children`） |
| 角色/职务 | 轻量字典表常驻内存，首次访问惰性拉取 |
| 搜索 | 服务端 LIKE 分页按需检索，结果回填 LRU 缓存 |
| 失效通知 | 中心数据变更 → `POST clientUrl + /sso/janus/openApi/notify` 推送（固定路径；client + 时间窗 + HMAC 签名校验）→ 用户/机构精准失效指定 ID、角色/职务重置；失败降级为失效，下次访问惰性回源兜底 |

业务代码完全无需感知上述细节；如需强制刷新，见监控页操作。

## 八、客户端自助注册

应用启动就绪（`ApplicationReadyEvent`）后，注册器自动向 `{server-url}/sso/janus/openApi/register`
发起**幂等 upsert**，上报 `client / secret-key / client-url / notify-path / app-name`：

- 网络失败（中心未起/抖动）：指数退避重试（2s 起，×2，封顶 60s），守护线程执行，**不阻塞业务**。
- 业务拒绝（认证中心返回非 200 code）：停止重试并 ERROR 告警，需人工核对 `janus.client.*` 配置；secret-key 变更属于正常覆盖更新（最新注册为准），不会触发拒绝。
- 注册状态可在监控页查看（PENDING / RETRYING / REGISTERED / REJECTED）。

## 九、监控页

默认开启。访问（免登录）：

- `GET /sso/janus/monitor`：聚合返回配置（密钥打码）、注册状态、在线会话、三类缓存内容、最近通知事件（JSON）。
- `/sso/janus/monitor.html`：starter 内置页面，可视化查看与操作。
- `POST /sso/janus/monitor/cache?domain=all|user|org|role&action=clear|refresh`：手动清空或重新拉取缓存。

如需整体关闭：`janus.client.monitor-enabled=false`。

## 十、常见问题

1. **切换系统后 401 / 会话互相覆盖？**
   同 IP 同域部署多个业务系统时，starter 已按 `client` 派生 token 名（`{client}-satoken`）避免冲突；
   请确认各应用 `client` 配置互不相同。

2. **`/sso/login` 验票返回 404 或验签失败？**
   检查 `server-url` 是否指向正确中心（starter 会自动补 `/api`，无需手填）；
   确认 `secret-key` 与中心注册值**完全一致**。

3. **注册一直 RETRYING？**
   认证中心尚未启动或网络不通，注册器会持续退避重试，中心就绪后自动成功。

4. **注册直接 REJECTED？**
   `secret-key` 与中心不一致，或 `client` 已存在但密钥冲突，请核对配置。

5. **`searchUsers` 抛异常？**
   需开启 `janus.client.user-full-load=true`（默认开启）。

6. **`UserContextHolder.get()` 为 null？**
   该路径未被拦截器拦截（在 `exclude-paths` 中）或在异步线程中；需要身份保证请用 `require()`。

7. **已登录但突然 401？**
   用户可能在中心被删除/停用；拦截器会按"用户不存在"返回 401。

## 十一、最小可用配置示例

```yaml
janus:
  client:
    server-url: http://janus.example.com
    client: my-app
    secret-key: ${JANUS_SECRET_KEY}
    client-url: https://my-app.example.com
    app-name: 我的应用
    # 以下均为默认值，可省略
    monitor-enabled: true
    user-full-load: true
    cache:
      max-size: 50000
      expire-hours: 12
```
